**Date:** 2026-10-17 (Eastern). ## Implemented security corrections

On PR #2 and inherited PRs #3/#4:
- Create store directories, markers, CAS shard directories, objects and stages with **protected DACLs at creation**; do not rely on permissive Windows inheritance, shelling out to icacls, or retroactive chmod.
- Accept only explicit full-control allow ACEs for the current user SID, SYSTEM and local Administrators, with expected owner and protected DACL; fail closed on foreign or inherited ACEs, null DACL, modified permissions, and inspection errors. The trust boundary explicitly excludes malicious same-user processes and privileged Windows principals (see FOSS-487).
- Correct unsafe FFI details: align the TOKEN_USER output buffer to a native pointer, ensure the token SID pointer and variable-length SID remain inside the output buffer, and bound the SID contained in each ACCESS_ALLOWED_ACE **before** passing it to EqualSid.
- Use validated UTF-16 paths (no embedded NUL) for Win32 MoveFileW no-overwrite checkout publication. Normalize Windows ERROR_ACCESS_DENIED/FILE_EXISTS/ALREADY_EXISTS to E_ALREADY_EXISTS **only after validating an actual non-reparse destination**; do not mask nonexistent destination or redirecting links.
- Native Windows-only negative tests and PowerShell evidence runner now assert ACLs at creation and after restoration, inject Everyone:Modify into metadata, marker, CAS root/shard and blob, deny junction paths, path traversal, reserved Windows device names and casefold collisions, and require exactly one successful checkout publication among 20 contenders.

Microsoft documentation was consulted for the TOKEN_USER buffer contract and ACCESS_ALLOWED_ACE layout (GetTokenInformation; ACCESS_ALLOWED_ACE, ACE_HEADER/AceSize). Source review is **not** independent security approval, nor native runtime proof.

## Release blockers (not waived)

1. **Native Windows NTFS execution:** on a provisioned Windows 10/11 or Windows Server NTFS workstation, run `qa/windows/README.md` and `qa/windows/M1-Qualification.ps1`. Run Windows Cargo tests, compile/link the actual Windows CLI, inspect the raw DACL output and re-run any failing ACL, junction, reserved path and no-overwrite tests. The current workspace cannot operate a native Windows OS.
2. **Native Windows recovery/durability:** process-kill/restart and platform-specific flush/recovery testing. Linux SIGKILL success cannot establish Windows storage durability or power-failure behavior.
3. **Independent security signoff:** separate reviewer must evaluate the Win32 FFI ownership/ACL policy, test implementation, same-principal race threat model, cryptographic provenance limitations and archived evidence. GitHub PRs #2/#3/#4 currently have no submitted reviews.
4. **Protected authority boundary:** FOSS-487 documents the same-OS-user and pathname-TOCTOU limits, which must not be misrepresented as full multi-agent isolation. These limits should inform FOSS-478 and FOSS-479 architecture.

No PR #2/#3/#4 merge is authorized until the mandatory gates are satisfied. The next production increment, FOSS-478 independent evidence verification, stays blocked; an SDD-only refinement is safe before then.

## Superseding final ACE-source verification (2026-10-17)

Security review identified a remaining ambiguity: the initial Windows ACL checker accepted allow-ACE flags other than `INHERITED_ACE`, permitting a modified `INHERIT_ONLY` ACE to satisfy an access-mask comparison even though it would not apply to the current object. The implementation now rejects reparse points directly and requires **exactly the explicit ACE inheritance flags that creation used**: object+container inherit for managed directories; none for managed files. No implicit auto-correction is performed.
