# OpenScion architecture — SPEC-000 / draft 0.1

## Operating model (original specification)
```text
Agent sandbox --propose(intent, delta, base)--> Proposal API
                                                 |
                                         immutable CAS object store
                                                 |
Verifier (trusted test runner) ---- evidence ---> Gate evaluator
Policy snapshot + reviewer approval -----------> |
                                                 |
                              Promotion API: expected_head CAS
                                                 |
                      protected channel head + audit receipt
                                                 |
                     materializer / explorer / deployment
```
**Trust boundary:** the agent produces untrusted code and change intent. It MUST NOT be able to forge verified evidence or independently approve changes to a protected channel. Server-owned policy and trusted executors establish promotion eligibility.

## Entities (schema-level, not finalized serialization)
- **Blob:** opaque bytes; ID = `SHA-256("openscion:blob:v1\\0" || length || bytes)` (domain-separation design under review). Store atomically, verify bytes on every trust-boundary read.
- **Snapshot:** canonical ordered path→blob-ID entries with mode/type and normalized, collision-free path encoding; its ID covers its canonical form. No dangling parents, nonregular files, path escape or mutable external references.
- **Revision:** hash-identified immutable tuple of snapshot-ID, parent revision IDs, proposal-ID, author claim and model-independent metadata; parent linkage is verifiable.
- **Intent:** declared goal, base revision, permitted paths, agent execution ID and human sponsor; cannot grant itself authority.
- **Proposal:** content-identified candidate edits + intended base, fully inspectable and not authoritative.
- **Evidence:** subject revision digest, verifier identity, suite version, timestamp, execution environment reference, test outputs digest and assertion results; `asserted` ≠ `verified`.
- **Policy decision:** policy digest + subject digest + independent reviewer/approver identities + allow/deny + expiry + reason.
- **Promotion receipt:** previous channel revision, next revision, expected revision, policy decision, immutable evidence references, verified actor and ordered event sequence.
- **Channel:** deliberately limited mutable reference: `channel_name → (head_revision, sequence)`. Never expose mutable channel updates to agents directly.
- **Rollback:** a compensated promotion referencing a previous known-good revision and requiring equivalent independent gate authorization.

## State machine and invariants
```text
DRAFT -> PROPOSED -> VERIFIED -> APPROVED -> PROMOTED
                 \-> REJECTED       \-> STALE
PROMOTED -> REMEDIATED_BY_NEW_PROMOTION (prior event remains)
```
- Candidate creation cannot move any protected head.
- CAS requires `current_head == expected_head`; if false, reject without partial effects.
- Evidence and policy decision must bind the **exact candidate content digest**, not just a branch label.
- A recorded denial never silently becomes approval after policy, evidence, or ancestry changes.
- Commit durable payloads before visible head movements; promote transaction and receipt must be consistently recoverable.
- Revision graph is acyclic; parent IDs must resolve; all accepted object IDs verified.
- Every materialization path is relative, normalized and within isolated workspace boundaries.

## Failure model / crash handling
Pre-write crash: channel unchanged. Blob write interrupted: temp object ignored/garbage collected. Candidate stored but no promotion: harmless orphan, reclaim only with documented retention. Promotion failure: never allow receipt without head or head without receipt; implement with a single atomic transaction or checked write-ahead recovery protocol. Recovery validates object and event hashes; failure is fail-closed.

## Security threats / intended mitigations
| Threat | Required mitigation | Negative-test evidence |
|---|---|---|
| Compromised agent fakes tests | independent verifier binds signed/validated evidence to digest | deny self-asserted pass |
| Agent self-promotion | author/reviewer separation and server auth | deny missing independent reviewer |
| Concurrent stale candidate | compare-and-swap expected head, no blind merge | one winner, one conflict |
| History tamper / rollback erasure | immutable event chain, offline signed checkpoints later | mutated event rejected |
| Path traversal / symlink attack | normalized relative regular paths only, no follow/escape | traversal refused |
| Content corruption | digest on read, canonical serialization | swapped bytes refused |
| Retry/replay promotion | idempotency key and unique event subject/sequence | replay does not re-promote |
| Unauthorized sensitive subdirectory | server-enforced scoped capability | cross-scope read/write denied |
| Cache poisoning | verify digest on retrieval, cache never authoritative | malicious cache rejected |
| Dependency or build supply-chain | approved dependencies, isolated trusted builder, attestations | mismatched digest rejected |

## M1 interfaces (proposed)
```
openscion init <repo-path>
openscion propose --base <revision> --intent <file> --changes <manifest>
openscion show <proposal-or-revision>
openscion verify <revision>
openscion gate --revision <id> --policy <file> --evidence <file>
openscion promote --channel main --expected <revision> --revision <id> --decision <id>
openscion rollback --channel main --expected <revision> --to <known-good> --decision <id>
openscion materialize <revision> <workspace-path>
```
CLI shape is provisional; API must preserve machine-parseable typed errors, JSON output and stable exit status.

## Capacity and performance questions
Benchmark N concurrent proposals, delta bytes, object-lookup latency, selective path reads, unique/deduplicated bytes, object-store contention, promotion CAS p99, and recovery time. No target performance numbers asserted until workloads are measured.

## Compatibility
Git import/export is an adapter. Preserve origin hashes and authorship **as source claims**; do not equate imported Git commit hashes with native OpenScion IDs or claim signatures verified without verification.

## Status
This is a design contract for SDD review. No code, passing tests, or deployment readiness are claimed.
